In a `ranked` CTE compute `es.weight_kg * (1 + es.reps / 30.0) as sql_e1rm` — use `30.0` float division NOT integer `30` (Pitfall 3); this column is INTERNAL ordering/flagging only, NEVER returned. Order candidates by the SQL e1RM expression `weight_kg * (1 + reps/30.0)` desc and take the top per `exercise_id` (`distinct on (exercise_id) ... order by exercise_id, sql_e1rm desc` — the 0006 `distinct on` precedent). RAW sets only; JS computes the e1RM hero max + earliest-vs-best delta (D-16). Order by `completed_at`.

    (4) `get_session_pr_flags(p_session_ids uuid[])` returns table `(session_id uuid, has_pr boolean)`. Reuse the SAME chronological running-max engine as RPC (1) but PARTITIONED PER EXERCISE so the PR-at-log-time semantics are identical (a set is a PR iff its sql_e1rm strictly exceeds the running max of all strictly-prior working sets for the SAME exercise across the caller's finished sessions): in a `ranked` CTE over ALL the caller's working sets, compute `sql_e1rm` (float `30.0`) and `was_pr = coalesce(sql_e1rm > max(sql_e1rm) over (partition by es.exercise_id order by es.completed_at, es.id rows between unbounded preceding and 1 preceding), false)`; the `partition by exercise_id` is what makes "PR" per-exercise (without it a heavy bench would suppress a squat PR). Then aggregate to session granularity: `select s.session_id, bool_or(s.was_pr) as has_pr from ranked s where s.session_id = any(p_session_ids) group by s.session_id`. Returning only the requested sessions (`= any(p_session_ids)`) keeps it cheap; RLS still scopes the ranked CTE to the caller (INVOKER), so a caller passing B's session_ids gets zero rows for them. NULL/empty array → empty result (no error). This is the history-LIST aggregator (one call over the visible session-id list) — it does NOT return e1RM (D-08), only the boolean flag.
