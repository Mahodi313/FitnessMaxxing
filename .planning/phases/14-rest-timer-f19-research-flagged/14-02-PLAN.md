<objective>
Build the native + state spine of the rest timer: a thin `expo-notifications` wrapper (`notifications.ts`), the single-owner Zustand store (`rest-timer-store.ts`) that holds `endTs`/`notificationId` and drives schedule/cancel/reschedule through the wrapper, and the app-scope `_layout.tsx` wiring for the foreground handler + tap-to-deep-link response listener.

Purpose: TIMER-03 (the backgrounded ping) + TIMER-05 (cancel/reschedule on skip/next-set) live here. The store is the cross-React-tree owner so `onKlart` (Plan 04) can fire `getState().start(...)` and the banner controls call `.skip()`/`.extend()`. The notification-tap deep-link (D-15) is the new attack surface — the tap target is an in-app route only, with `data.sessionId` validated before routing (M4 anti-phishing).
Output: `app/lib/notifications.ts`, `app/lib/rest-timer-store.ts`, extended `app/app/_layout.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS notification payload → app | `data.sessionId` arrives from a system-delivered notification tap — untrusted until validated |
| app → OS notification scheduler | scheduled local notification content is rendered on the lock screen (privacy surface) |
| iOS permission grant → app | new OS-permission surface (notification authorization) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Spoofing/Tampering | notification-tap deep-link (`_layout.tsx`) | mitigate | Tap target is an in-app expo-router route `/(app)/workout/${sessionId}` ONLY — never `Linking.openURL` of an external URL (M4 anti-phishing). `data.sessionId` validated as a non-empty string before `router.push`; routes only into the authenticated `(app)` group (RESEARCH §Security Domain) |
| T-14-04 | Information disclosure | notification content (lock screen) | mitigate | D-15: body is generic i18n text; `data` carries ONLY `{ sessionId }` — no exercise/weight/PII on the lock screen (RESEARCH §Security Domain V8) |
| T-14-05 | Reliability (Tampering-adjacent) | stale notification after skip/reschedule | mitigate | `cancelNotification(oldId)` before every reschedule + clear stored id on skip (Pitfall 6); finish-cancels-on-session-end |
| T-14-06 | DoS | duplicate response listeners under Fast Refresh | mitigate | globalThis sentinel teardown (network.ts `APPSTATE_BGFLUSH_KEY` precedent) — one listener, one route push per tap (Pitfall 7) |
| T-14-07 | Elevation/Spoofing | scheduling without granted permission (silent no-fire) | mitigate | Delivery is gated by D-14 at schedule time; permission read via `getPermissionsAsync().granted` / `canAskAgain` (Pitfall 3) — denied state surfaced informationally (D-12), not relied on for security |
</threat_model>
