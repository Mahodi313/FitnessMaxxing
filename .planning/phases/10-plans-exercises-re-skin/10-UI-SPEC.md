# Phase 10 — UI Design Contract (Plans & Exercises Re-skin)

> Visual and interaction contract for the Forge re-skin of the plan/exercise CRUD screens, surfacing the schema fields v1 hid (muscle group, equipment, targets, descriptions). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** `app/design v2/Sources/design/forge-screens.jsx` — the in-scope reference screens: `FHome` (plan list, line 88), `FPlanDetail` (line 223), `FNewPlan` (line 1113), `FExercisePicker` (line 1215, search + filter pills + create-new CTA + list), `FExercisePickerNew` (line 1334, name / muscle-dropdown / equipment / notes), `FExerciseEdit` (line 1438, sets/reps steppers + target chip + notes + remove), `FStepperInput` (line 1553), `TabBar` (in `lib.jsx`). Tokens/type/spacing are inherited verbatim from **`.planning/phases/08-forge-foundation/08-UI-SPEC.md` (status: approved)** and the live `app/tailwind.config.js` `forge.*` block — this phase does NOT re-derive tokens.
>
> **Phase boundary (from 10-CONTEXT.md):** Re-skin **plans list / Planer tab** (`index.tsx`), **plan detail** (`plans/[id].tsx`), **new-plan** (`plans/new.tsx`), **exercise picker** (`plans/[id]/exercise-picker.tsx`, incl. inline create-new), **plan-exercise edit** (`plans/[id]/exercise/[planExerciseId]/edit.tsx`), and the **tab bar** (Planer / Historik / Inställningar). Surfaces existing-but-hidden fields + adds: fixed 5-key bilingual muscle-group taxonomy, muscle-group filter pills, curated bilingual seed library, hard-delete for plans (alongside archive), and full sv+en i18n of every touched screen. **Out of scope:** active-workout screen (Phase 11), Home activity-ring dashboard widgets (Phase 12), global exercise-library import (deferred), global i18n audit (Phase 15). No net-new primitive families this phase — the only new composed controls are the **muscle-group filter pill row**, the **muscle-group dropdown**, and the **`FStepperInput`** stepper, all built from existing tokens.

## Spacing Scale

Inherited verbatim from Phase 8 (`08-UI-SPEC.md §Spacing Scale`). Layout values are 4-multiples; sub-4 and the optical values below are hairline/component-dimension insets read directly from the reference screens. Border-radius uses the locked `forge-sm/md/lg/xl` tokens.

| Token | Value | Usage (this phase) |
|-------|-------|--------------------|
| xs | 4px | Icon gaps, chip inner gap, progress-dot gap |
| sm | 8px | Section-header → list gap; exercise-row gap (plan detail `gap 8`); stepper-row gap; filter-pill gap (6px optical) |
| md | 16px | Screen horizontal padding (cards live at `0 16px`); picker/edit body padding |
| lg | 20px | Title-block horizontal padding (`12px 20px`), card inner padding (`16–20px`), new-plan body padding (`24px 20px`) |
| xl | 24px | Section padding; new-plan field-stack gap (`20`), target-chip bottom margin |

| 3xl | 100px | Plans-list (tab screen) bottom padding (clears floating TabBar — `FHome` `0 0 100px`) |

**Border-radius (locked `forge.radius` — `tailwind.config.js`):**

| Token | Value | Usage |
|-------|-------|-------|
| forge-sm | 10px | Icon tiles on plan-card / exercise-row (`barbell` tile), muscle dropdown chevron tile, stepper `±` tiles (radius 8) |
| forge-md | 14px | `ForgeField`, search field (height 48), filter pills (radius 18 optical), exercise-list rows, picker create-new CTA, stepper container, secondary/remove button (radius 14) |
| forge-lg | 20px | Plan cards (radius 18 optical), plan-detail exercise rows (radius 16), hero card, primary CTAs (radius 16–18) |
| forge-xl | 28px | (not used this phase) |

**Exceptions (optical — from reference screens; do NOT normalize to the 4-grid):**
- Plan card padding `16px 18px`, radius 18; plan-card icon tile `44×44` radius 12.
- Plan-detail exercise row padding `14px 14px`, radius 16; index tile `32×32` radius 8.
- Picker search field height `48`, radius 14; filter pill padding `6px 12px`, radius 18, gap 6; create-new CTA padding `12px 16px`, radius 14 (dashed border).
- Picker exercise-row icon tile `36×36` radius 10; row add-button `30×30` radius 15.
- New-plan name field `56` tall (focused = `2px accent` border); description box `minHeight 110`; notes box `minHeight 92`.
- `FStepperInput`: container `120×64` radius 14 (`borderStrong`), `±` tiles `32×32` radius 8 (`−` on `surface2`, `+` on `accent`).
- Target preview chip padding `6px 12px`, radius 10 (`accentSoft`).
- Primary CTA heights: plan-detail "Starta pass" `64`; new-plan / picker-create `60`; remove-from-plan `52`.
- Nav-row circular buttons `40×40` radius 20; plans-list avatar/profile button `36×36` radius 18; brand tile `32×32` radius 10.
- Touch targets: every icon-only control (stepper `±`, row add `+`, nav chevrons, overflow `ellipsis`) ≥ 44px hit area even where the visible tile is smaller.

> **Implementation note (NativeWind 4 / Tailwind 3 purge):** the non-4-multiple optical values above (`18`, `14`, `6`, `30`, `36`, `44`, `52`, `56`, `60`, `64`, `92`, `110`, `120`) MUST be applied as literal inline `style={{ }}` numbers, **NOT** as Tailwind arbitrary classes (e.g. avoid `h-[64px]`, `gap-[6px]`, `p-[14px]`). NativeWind 4 on Tailwind 3 purges arbitrary classes whose values are off the configured scale by default, so an arbitrary-class form would silently drop. Inline `style` is the reliable carrier for optical exceptions. (Phase 4/9 precedent.)

## Copywriting Contract

All strings render through `t()` against `app/locales/{sv,en}.json` (I18N-01 / I18N-05 / D-15). Swedish is the primary locale; English must fit the same layout without overflow. **User-created content (plan names, descriptions, exercise names, notes, free-text equipment) is stored as written and rendered verbatim in both languages — never auto-translated (D-16).** Only keyed values flip: the 5 muscle-group keys (D-01) and seed-row name/equipment (D-06).
