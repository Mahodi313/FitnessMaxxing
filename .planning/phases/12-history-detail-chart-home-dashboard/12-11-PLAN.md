<objective>
Close FIT-111 (minor): changing the weight unit (kg↔lbs) in Settings does not re-render already-displayed figures until the app restarts. Conversion VALUES are correct; only the reactivity is missing.

Root cause (confirmed in code): every consuming screen reads the unit pref with the same non-reactive idiom — a local `useState<UnitPref>("metric")` seeded once by `useEffect(() => getPref("fm:units").then(setUnit))` (history.tsx L118-130 `useUnitPref`, index.tsx L794-803, [sessionId].tsx L106-108, chart.tsx L164-167). `getPref` reads AsyncStorage once on mount with no subscription, so `formatWeight`/`formatVolume`/`toDisplayVolume` only re-run when the screen remounts. settings.tsx `onUnitsChange` (L268-271) writes `setPref("fm:units", value)` to AsyncStorage but nothing notifies the other screens — they keep the stale `units` state until restart.

Purpose: Introduce ONE reactive source of truth — a tiny Zustand store (`useUnitStore`) holding the live `UnitPref` — that all four read-side surfaces subscribe to, mirroring the existing `font-store.ts`/`persistence-store.ts` precedent (Phase 3 D-08: Zustand for cross-component reactive state). Settings writes through the store's `setUnit` action (which updates state AND persists `fm:units` via the existing `setPref`). AsyncStorage stays the durable source; the store is the live in-memory mirror hydrated at boot (UnitsBootstrap, ThemeBootstrap precedent). Toggling the unit now re-renders every figure immediately because each consumer is subscribed.

This is the lowest-risk approach consistent with existing patterns: it reuses the established Zustand-store + Bootstrap idiom (theme/locale already work this way) rather than inventing a new mechanism, keeps `fm:units` as the persisted pref, and does not touch any TanStack query or the F13 hot path (D-24).

Output: new `app/lib/units-store.ts`; a `UnitsBootstrap` in `_layout.tsx`; settings writes via the store; four consumers swap their local `useState+getPref` for a `useUnitStore` selector.
</objective>
