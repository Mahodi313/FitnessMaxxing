# Milestone v2.0: Forge Redesign

**Status:** ✅ SHIPPED 2026-06-17
**Phases:** 8-15
**Total Plans:** 41

## Overview

v2.0 rewrote the entire app UI to the "Forge" design system (premium, Apple-Fitness DNA, dark/light parity, orange accent), exposed data fields the v1 UI never showed (muscle group, equipment, set/rep targets, descriptions), and added a Home dashboard, PR celebration, a rest timer, and English — all while leaving v1's offline-first write path and the F13 "never lose a set" guarantee completely untouched (`npm run test:f13-brutal` stayed green every phase). Sequencing was infrastructure-first, then re-skin low-risk → high-risk, then net-new features, then bilingual + release hardening last. App Store launch (Apple Sign-In / TestFlight) remains a later milestone.

## Milestone Summary

**Decimal Phases:** None — all v2.0 phases were planned integers (8-15).

**Key Decisions:**

- **Token-driven re-skin via `tailwind.config.js` (`THEMES.forge`)** — Forge light+dark token parity using `forge-<token>-light` base + `dark:` sibling `forge-<token>` DEFAULT, so every screen inherits dark-mode for free (established Plan 08-04, first forge.* consumer).
- **i18n = UI-text only; user content stored as written** — react-i18next + expo-localization; plan/exercise names and notes are never auto-translated (I18N-05). Three-state language resolver (System/sv/en) overrides device locale live with no restart.
- **Reactive units store (Zustand, no persist) for live kg↔lbs** — `app/lib/units-store.ts` holds the live display unit so a Settings toggle re-renders every read-side figure immediately; storage stays canonical kg, conversion is display-only (D-20/FIT-111).
- **PR detection is client-side and offline-safe** — Epley e1RM in `app/lib/e1rm.ts` (the single formula source, D-08); no persisted `is_pr` column (derivable from sets, avoids schema/sync complexity). PR-at-log-time flagged via strictly-prior SQL window frame.
- **Rest timer survives JS suspension via absolute timestamp + scheduled OS notification** — countdown re-derives `remainingMs` from a stored `endTs` vs now (not a JS interval); a DATE-trigger local notification fires when rest ends; cancel-before-reschedule on every transition. Fail-soft notifications wrapper never rejects into fire-and-forget callers.
- **Inline-overlay UX preserved (NOT Modal portals)** — every finish/draft-resume/saved-toast/PR-banner/rest-banner overlay renders inline so the F13 write path and gesture/freezeOnBlur behavior stay coherent (carried from v1.0).
- **Read-side RPCs are RLS-scoped + SECURITY INVOKER + `search_path=''`** — dashboard + chart + PR aggregates computed server-side, finished-only, `set_type='working'`; no cross-user aggregation (3 new migrations: 0010/0011/0012).

**Issues Resolved:**

- FIT-109 — Home ring/count stale after finishing a session (dashboardKeys not invalidated in the finish onSettled).
- FIT-110 — session-detail → exercise-chart cross-link dropped in the 12-07 re-skin (chart route orphaned; MOTN-03 unreachable).
- FIT-111 — kg↔lbs toggle required a restart to re-render figures (non-reactive per-consumer getPref reads).
- FIT-116 — active-workout PR trophies were ephemeral useState and vanished on navigation (now derived from persisted sets via running-max replay).
- FIT-128 — rest-banner countdown wrapped to two lines; sizing moved to className (NativeWind drops style() box props on Pressable).
